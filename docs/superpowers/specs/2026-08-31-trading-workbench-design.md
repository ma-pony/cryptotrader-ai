# 交易工作台与可扩展配置设计规格

日期：2026-08-31

状态：设计已确认，已进入文件级实施计划阶段；尚未实施。

本次补充：账户资产与收益、人工退出、多币种资金约束、信号效果复盘、回测结果和即时告警。沿用六个主入口。

## 1. 目标与范围

重做现有页面的信息组织、日常操作流程和接口契约，使页面对应现在的交易架构：多个信号组件共同形成判断，同一判断可以交给多个资金池及交易账户执行。

用户进入系统后，应能回答四个问题：现在是否在运行；最近为什么形成这个判断；哪些操作需要我处理；实际涉及哪些账户和资金。

本期约束：

- Kronos、LLM 四智能体和后续自定义组件是同级信号来源。LLM 内部辩论保留。
- 组件信任权重、平台连接、资金分配、人工审批及运行策略在网页配置，持久化到数据库。
- 新增信号类型或平台类型通过后端代码实现和注册。本期不做插件安装、市场、包发现、热加载或浏览器上传代码。
- 新增平台必须能在网页配置。完成这次通用前端改造后，再增加符合契约的平台，只需改后端，前端代码和构建产物保持不变。
- 模拟账户和真实账户可以同时存在，不设置全局互斥的“模拟／实盘模式”。真实下单另有明确授权。
- 沿用一套全局决策引擎，向多个资金池分发结果。本期不引入多策略工作区、每池独立信号组合或可视化节点编排。
- 第一期开通从配置、模拟交易到持仓管理、收益核对和人工退出的完整流程。信任权重仍由用户调整，不做自动调权、参数寻优或复杂绩效归因。
- 直接替换旧流程，不长期维护双套页面、双套业务规则或兼容路由。

本规格不授权修改运行数据库、启用交易、调用付费模型、提交订单、重启服务或提交推送代码。涉及这些操作时另行确认。

## 2. 领域对象与判断流程

```text
行情与上下文
  → 启用的信号组件：Kronos / LLM 四智能体 / 自定义组件
  → 信任权重融合 → 目标仓位
  → 各资金池：账户快照 → 风险约束 → 调仓计划
  → 按资金池配置决定是否人工审批
  → 各平台账户执行 → 同一条决策记录
```

“仅分析”在目标仓位产生后结束，不进入账户访问、资金池计划、审批或订单执行。

| 对象 | 职责 | 页面用语 |
| --- | --- | --- |
| 信号组件 | 根据共同市场上下文独立输出方向、置信度与证据 | 信号组件 |
| 决策引擎 | 管理组件、融合、全局风险参数与自动运行条件 | 决策引擎 |
| 平台类型 | 后端实现的平台能力及其配置声明 | 交易平台 |
| 平台连接 | 某个平台、环境、账户凭据与连接参数的实例 | 账户连接 |
| 执行资金池 | 将目标仓位分配给一组账户，管理人工审批及本池风险状态 | 资金池 |
| 决策记录 | 保存一次分析或交易运行的输入摘要、结果与执行过程 | 决策记录 |

同一平台可建多个连接，例如同一交易平台的官方模拟账户和真实账户、同环境下的两个不同账户。行情来源独立配置，不随交易平台选择而隐式切换。

### 数字的含义

- 信任权重：用户配置的组件影响占比，启用组件合计 100%。组件失败不自动提高其他组件的占比；本期保留失败即不进入交易的规则。
- 置信度：组件对本次输出的自评，不等同于预测胜率。
- 加权贡献：组件方向、置信度与信任权重形成的带符号贡献。融合结果由后端计算，前端展示。
- 资金分配比例：同一资金池内各账户的目标资金分配，合计 100%。与组件信任权重分开命名、分开展示。
- 目标仓位：内部保留 `target_exposure ∈ [-1, 1]`，页面写“目标做多：权益的 30%”“目标做空：权益的 20%”或“目标持仓为零”。不直接让用户填写内部小数。
- 目标为零可能触发现有仓位平仓。“无方向信号”不能直接翻译成“维持不动”；只有调仓差额为零才显示“无需调仓”。做空与持仓为零分别表达。

## 3. 页面结构

主导航收敛为六项。资金状态、决策过程和配置入口各有一个主位置，通过链接关联，不复制业务实现。

| 主入口 | 内容与子页面 | 原页面去向 |
| --- | --- | --- |
| 工作台 `/` | 运行状态、待审批事项、最近决策、分资金性质的账户概况 | 重做首页；初始化提示融入首页 |
| 决策记录 `/decisions` | 列表、筛选、详情、组件证据、资金池计划与执行结果 | 合并 decisions、cycles、debate |
| 决策引擎 `/engine` | 行情与上下文、信号组件、融合与风控、自动运行 | 合并 strategy、行情配置、风险配置、两个调度入口 |
| 账户与资金池 `/accounts` | 连接配置、持仓与订单、成交收益、人工退出、资金池与真实下单授权 | 合并平台连接、execution-books 与账户风险展示 |
| 研究与验证 `/research` | 市场观察、仅分析、回测历史与配置效果比较 | 整合 market、backtest；移除当前会触发交易周期的聊天入口 |
| 系统设置 `/settings` | 模型服务、通知规则及送达状态、访问安全、运行指标、智能体资料 | 整合 models、system、metrics、memory 的有效功能 |

通用详情地址：`/engine/components/:componentId`、`/accounts/connections/:connectionId`、`/accounts/books/:bookId`、`/decisions/:decisionId`。它们不能绑定具体组件或交易所名称。

旧 `/setup` 的强制跳转取消。未就绪、暂停自动运行或尚未启用交易时，也能看首页、历史、账户配置和缺项说明。

旧 `/risk` 的有效内容进入资金池详情或引擎风险配置。没有接入当前执行链的旧熔断开关和重置按钮不保留。旧“记忆”功能按真实数据用途命名为智能体资料，不声称模型发生了记忆演化。

本期不保留独立聊天入口。后续若增加“解释本次决策”，应读取已有记录并调用专用解释服务，不能复用交易触发接口。

## 4. 工作台与第一次使用

### 日常进入的画面

顶部显示“自动运行已暂停／自动运行中”、最近一次运行时间、当前配置是否已应用。核心操作为“仅分析一次”和“开启／暂停自动运行”；“运行一次交易”单独呈现，并列明影响范围。

正文先放待处理事项，再放最近决策。模拟资金与真实资金分区汇总，各自标明账户与估值时间，不计算一个混合总资产。

最近决策摘要包含交易对、触发来源、组件方向与贡献、最终目标、资金池处理结果。点击同一条记录进入完整过程，不能分别跳到三个不同页面查信号、辩论和执行。

例如，已经保存并检查成功的官方模拟账户如果尚未加入资金池，显示“已连接，未参与执行”，操作为“分配到资金池”。不能仅因凭据齐全就写“正在交易”。这是正常配置状态，不作为连接故障。

### 首次配置的渐进流程

1. 配置行情、选择信号组件及其依赖。只要求启用组件需要的模型服务和上下文来源。
2. 就绪后开放“仅分析一次”。提示可能产生模型调用费用，无须先配置交易账户。
3. 创建模拟账户连接，保存完整参数与凭据后自动只读检查。
4. 建立资金池、分配账户、设置人工审批。页面展示尚未启用交易。
5. 用户明确选择“运行一次交易”，确认账户与资金性质后运行；审批或结果均可在工作台与决策详情追踪。
6. 用户自行开启自动运行。保存配置、通过连接检查都不能代替此操作。

第二次进入页面时，保留服务端的配置状态、凭据已配置标记、连接检查时间与结果。不要求用户重新输入密钥来证明已经配置。

### 次日复盘与退出场景

你第二天打开工作台，先看到昨晚的待审批和失败事项，再进入模拟资金池查看当前持仓、实际成交与收益。点开一笔成交能回到产生它的决策，查看 Kronos、LLM 四智能体及其他组件当时的判断。已经到评估时间的预测可以与后续行情对照，尚未到时间的明确显示“待评估”。

若决定退出某个账户的持仓，可以从同一页面停用所属资金池的策略执行，再确认指定账户、交易对和数量进行平仓。操作结果保留在账户历史中，资金池不会自动恢复运行。整个过程不要求读日志或编辑数据库。

## 5. 决策记录与组件展示

### 决策详情

详情按以下顺序展开：本次概况 → 组件结果 → 融合与目标 → 资金池风险与调仓计划 → 审批与订单结果。

只分析的记录在目标处结束，明确显示“仅分析，未访问交易账户、未生成订单”。交易记录显示各资金池自己的结果；一个资金池成功不能掩盖另一个失败。

每条记录保存交易对、运行模式、触发来源、时间、配置版本、组件结果及安全的配置摘要。查看旧记录时使用当次快照，不拼接当前权重、模型配置或平台名称作为历史事实。

组件失败需保存失败的组件、阶段及可供用户理解的脱敏原因。门控跳过预测、返回无方向信号、外部请求失败分别展示。

### Kronos 的独立入口

“决策引擎 → 信号组件 → Kronos”包含概览、运行历史和配置；工作台及决策详情均可进入。它使用通用组件详情模板。

概览重点展示：

- 最近一次输出的交易对、时间、方向、置信度、信任权重及加权贡献。
- 历史行情与未来预测曲线，明确区分真实数据区和预测区，标注预测起点、周期及预测步数。
- 门控结果、是否实际执行预测、信号过滤原因与已有置信度分项。
- 对应历史决策入口，方便核对预测产生时的上下文。

门控未通过时显示“本次未执行预测”及原因，不展示上一轮预测作为本轮结果。弱信号过滤后仍可展示本轮实际产生的预测曲线，并解释为何最终目标未采用该方向。

目前预测完整序列没有随组件结果持久化。实施时必须保存用于图表的历史采样、预测时间点与预测序列，查看或刷新历史页面不重新调用 Kronos。

### LLM 四智能体与自定义组件

四个智能体的判断、内部辩论和最终组件输出保存在 LLM 组件下。详情仍可查看发言顺序、观点差异和结论依据；四名智能体不自动变成四个全局加权组件。

所有组件使用相同的顶部摘要和配置入口。专用内容由后端输出有限的展示块：文本、指标组、时间序列图、表格、时间线。Kronos 使用时间序列和指标块，LLM 使用文本及辩论时间线。

每个块具有明确类型、中文标题和类型对应的数据结构；图表数据提供时间、序列名称、单位和预测分界。前端按块类型渲染，不按组件 ID 编写分支，也不执行后端提供的 HTML 或脚本。

本期新增组件可组合这些块。需要全新交互控件的能力属于后续通用渲染器扩展，不承诺任意界面都能只改后端。

### 信号效果复盘

组件详情增加“效果复盘”，按交易对、记录模式、配置版本和时间范围筛选。页面同时显示信号样本数、已评估数、无方向输出及失败／跳过次数，避免只展示成功样本。

本期使用统一的方向评估周期，默认等于全局行情周期，可在引擎网页配置。信号产生时冻结起始行情时间、参考价格、方向及评估截止时间；到期后用指定市场数据源的对应已收盘行情评估，禁止重新生成原信号。统计时分开不同评估周期和配置版本，回测样本与实时样本不混算。

方向命中率为“预测方向与到期价格变动同向的数量／已到期且价格完整的有方向样本数”；价格不变不算命中。无方向信号、跳过、失败和行情缺失不进入该分母，分别显示数量。零有效样本显示“尚无可评估样本”，不显示 0% 胜率。

Kronos 额外将保存的预测曲线与后续实际行情叠加，按对应时间点展示预测误差。原预测快照保持不变，后续行情及评估结果另存。自定义组件通过通用指标、表格与序列块展示可用评估内容，没有预测序列的组件无需伪造曲线。

每次结果显示组件耗时、调用失败及可获得的模型用量；费用仅在用量和计价信息完整时展示估算值，缺少信息显示“费用未知”。加权贡献解释判断如何形成，方向命中率用于检视历史输出，两者都不能标为该组件带来的实际利润。

## 6. 决策引擎配置

配置按行情与上下文、信号组件、融合与风险、自动运行四组组织。

组件列表展示是否启用、信任权重、依赖就绪情况、最近输出和错误。权重编辑使用百分比输入与合计提示，不把大段参数表直接铺在列表上。组件详情使用后端声明的普通字段和高级字段。

风险参数是全局引擎配置，按资金池完整账户快照执行；本期不新增每池风险参数覆盖体系。单品种目标上限、跨品种总敞口、实际保证金占用和回撤分别命名。总敞口必须计入该池全部持仓及未完成的增仓订单，不能只检查本次交易对，具体规则见第 10 节。

交易范围在引擎中配置，明确列出规范化交易对和现货／合约类型。“仅分析一次”“运行一次交易”都显式选择一个交易对，自动运行使用已保存列表。界面区分行情源支持与各账户可交易能力；某连接不支持品种时，阻止所属资金池对该品种执行并显示原因，不自动换品种或重新分配其账户权重。

自动运行包含时间间隔与条件触发规则，使用一个总开关。暂停同时阻止这两类来源发起新运行，保留规则定义，不停止只读服务，不撤销已提交订单，也不承诺中断已开始的执行。

配置在数据库保存后展示保存版本和应用状态。保存成功、运行时应用成功、交易功能已开启是三个不同事实。不能用一个绿色提示代替全部状态。

## 7. 账户与资金池：新平台也必须能网页配置

### 创建与编辑账户连接

用户点击“添加账户连接”，按顺序完成：

1. **选择交易平台**：选项来自后端注册目录，新增平台注册并部署后自动出现。
2. **选择账户环境**：选项由该平台声明，并说明属于模拟资金还是真实资金。显示“本地虚拟账户”“官方模拟账户”“真实账户”等中文名称，不让用户猜 Paper、Demo 的含义。
3. **填写连接参数**：账户名称、账户标识及平台声明的普通配置；可选高级参数折叠。只展示该平台支持的保证金模式、杠杆等能力字段。
4. **填写凭据**：按后端声明生成密码输入框，支持平台自己的字段名称、说明及必填要求，不固定为三种密钥。
5. **保存并检查**：普通配置与凭据分别持久化，页面通过一个操作顺序提交；凭据完整且保存成功后自动做只读连接检查。若凭据尚未填写，可保存连接基本信息并明确标为“待补全凭据”；不需要凭据的平台在连接保存后直接检查。
6. **查看结果**：展示“连接通过／连接失败”、检查时间、失败原因与下一步。参数保存成功而凭据写入失败时，分别说明结果，保留已保存的连接供继续填写。
7. **加入资金池**：检查通过后提供“分配到资金池”；选择或新建资金池，配置分配比例和人工审批。该操作不自动启用交易。

保存会影响连接的参数或凭据后，旧检查结果失效；完整新配置保存成功后自动再检查。尚未保存的表单修改标为“未保存”，不能沿用旧结果声称这些修改已通过检查。不因每次打开页面而无条件重复请求平台。提供“重新检查”供用户主动刷新。

只读检查使用该连接已保存的当前参数和凭据，通过适配器读取账户信息，验证连接及账户读取能力。它不提交试单，不验证全部交易权限，不声称覆盖所有交易品种。结果应与所检查的配置及凭据版本关联。

列表以紧凑行展示平台、环境、账户名称、检查状态、所属资金池与是否参与执行，详情中编辑。避免把每个连接的长表单同时展开。

### 凭据体验与安全

凭据成功保存后，显示“凭据已配置”和更新时间，默认展示“更换凭据”操作。进入更换状态后才出现空输入框，明确表示输入新值；空框不能被误解为原配置丢失。

凭据只写不回显，不进入普通配置草稿、历史快照或浏览器持久化缓存。保存请求失败时只保留本次编辑内存中的输入供重试；成功后清空。后端日志、校验错误和接口响应不得带回原值。

无凭据的平台不显示凭据区域。可选凭据字段遵循后端声明，不能把所有字段都按必填处理。清除整套凭据必须是单独明确的操作，普通空值提交不清除已保存凭据。

### 资金池与真实授权

资金池详情展示所用账户、分配比例、持仓与权益快照、风险状态、人工审批开关及近期执行。一个资金池只归属于一种资金性质，模拟与真实账户不混入同一个池。

连接检查通过不等于参与执行。是否启用连接、是否分配到资金池、资金池是否启用、真实下单是否授权应分别可见，并由后端给出不可执行原因。

真实下单授权单独呈现，说明其对启用中的真实资金池的影响。切换查看真实账户、添加真实连接或保存密钥均不能授予真实下单权限。

### 账户资产、订单与收益

账户详情设概览、持仓与订单、成交与收益、连接配置四个页签。持仓读取账户全部持仓，不受当前分析交易对筛选限制；每行明确账户、品种、市场类型、方向、数量、入场价格、估值时间与浮盈。未支持的品种也应可见并标为“仅展示，不可操作”，不能静默遗漏。

订单区区分普通挂单、止损／止盈保护单和已结束订单，展示平台状态、已成交数量与平均成交价格。关联到本系统决策的订单提供返回入口；外部手动交易标为“外部订单”，不能硬归入最近一轮决策。

账户同步服务独立于策略运行。启动后及后台定期只读同步账户状态、订单和成交，页面显示快照与最后成功同步时间，提供“刷新账户数据”。暂停策略、停用资金池或停止浏览器会话不应丢失这条同步链；凭据不可用时保留最后快照并标明更新失败，不显示为最新数据。

数据库保存按连接标识和平台成交标识去重的成交明细，记录品种、方向、数量、价格、费用币种、成交时间及可关联的订单／决策。资金费单独保存。当前订单和权益快照也持久化，重启后从数据库读取并向平台同步，不把上一轮订单返回值当作长期最新状态。

已实现收益从成交或平台明确提供的结算收益计算；本期本地计算采用移动平均持仓成本。手续费、资金费及浮盈分开展示，交易净收益按明确口径汇总。不可获得或不可核对的数据返回空值和原因，不能填零，也不能把权益差额直接当作交易收益。

资金池汇总关联账户的记录，并保留成交时的资金池归属；变更账户分配不改写历史。保留一个账户不能同时加入多个启用资金池的约束，防止重复计算权益。每条金额带币种，只有统一估值后的金额才能合计；未换算的费用显示原币种并注明汇总不完整。本期不做完整会计或税务系统，无法解释的资金变动不归为交易利润。

### 停用、撤单与平仓

第一期只提供明确的退出操作，不增加手动开仓交易终端：

1. 选择“撤销普通挂单”或“平仓”，明确账户及交易对，列出所属资金池和将受影响的其他账户。
2. 用户确认停用所属资金池。复用资金池启用开关，之后的定时、条件触发和“运行一次交易”都跳过该池；其他资金池继续按原配置运行。等待该池当前调仓结束后再读取最新账户状态。未加入资金池的账户先停用该连接的策略执行。
3. 页面展示实际待撤订单或待平仓数量，用户再确认具体操作。平仓前先撤销该品种可能改变仓位的普通挂单，并重新读取仓位；不先撤销现有保护单。
4. 后端通过平台适配器执行指定操作。衍生品平仓使用只减仓能力；现货卖出不超过当前可用持仓。下单前刷新校验，仓位已变化时返回新计划要求确认，不能用过期数量反向开仓。
5. 平仓后同步成交、持仓和保护状态；仅在确认持仓为零后清理对应保护单。失败时展示实际剩余仓位与保护状态，不能仅因请求已发送就显示平仓成功。

人工退出使用独立的撤单／减仓入口，不触发信号推理，不重新进入策略审批队列；用户对具体计划的确认即本次人工授权。真实账户操作仍要求真实下单授权。保存操作来源、时间、确认计划、实际结果及失败原因，并关联账户、资金池和相关原订单。

退出完成后资金池保持停用，只有用户明确恢复后策略才能重新开仓。只停用资金池或连接不会自动撤单、平仓，也不会隐藏现有资产；仍保留只读同步和历史查询。停用连接时先展示并停用其所属启用资金池，不自动把资金权重分给其他账户；无所属池时只停用该连接。移除资金池分配或删除连接前要求停用、无持仓、无挂单，历史记录不随配置删除。

## 8. 后端注册与通用前端契约

### 注册方式

后端维护信号组件和交易平台两个代码注册表。每项注册同时提供工厂、配置声明和能力说明，运行时创建对象与网页配置目录使用同一来源。

注册只加载声明，不连接平台、不加载预测模型或发起推理。后端部署后更新目录即可发现新增类型。现有外部 entry point 发现链路在本期替换，不要求开发者构建或安装插件包。

新增交易平台需要实现现有执行协议的相关能力、参数模型、凭据模型及环境声明。新增信号组件需要实现组件协议、参数模型、依赖声明和结果展示块。前端不维护平台或组件 ID 白名单。

### 配置目录需要包含的声明

| 声明 | 必要内容 | 前端用途 |
| --- | --- | --- |
| 类型信息 | 稳定 ID、中文名称、中文说明 | 选择器、标题及说明 |
| 普通参数 | key、类型、标签、说明、默认值、必填、范围／选项、单位、是否高级 | 通用配置表单 |
| 凭据字段 | key、中文标签与说明、必填、密码输入语义；无默认密钥 | 通用凭据表单 |
| 账户环境 | ID、中文名称、资金性质 | 选择环境、模拟／真实标识及账户分组 |
| 执行与账户读取能力 | 支持的市场类型、保证金模式、退出操作及可读取的账户／成交数据 | 显示适用字段、操作入口和数据缺项 |
| 组件依赖 | 所需行情字段、模型服务与上下文来源 | 就绪提示及缺项说明 |

普通字段复用现有文本、数字、整数、布尔、枚举、字符串列表能力与嵌套字段路径。服务端根据平台、环境生成适用声明，前端不增加平台专用判断。后端仍负责完整校验。

数据库与后端运行时保留完整参数；页面不提供“参数 JSON”输入框。接口仍以 JSON 传输结构化数据，用户只操作表单字段。展示块随每次组件结果保存，由决策或组件历史接口返回，不放入配置目录。

凭据提交必须贯通整个链路：通用表单 → 按字段 key 构成的只写载荷 → 平台凭据模型校验 → 加密存储 → 适配器读取。不能只把输入框做成动态，提交时又截取 `api_key`、`secret`、`passphrase`。

现有 `CredentialPayload` 和凭据接口改为承载平台声明的字段映射，各适配器自行声明所需字段。保留加密、密文绑定连接、脱敏错误及只返回配置状态的约束。目录不包含密钥值。

声明的能力是类型能力，不能替代运行时账户能力检查。实际下单仍受资金池风险、账户状态、平台返回权限和真实下单授权约束。

本期平台配置支持字段式参数与凭据，不做通用 OAuth 授权编排或任意交互脚本。

平台通用协议同时覆盖品种目录、账户级持仓与余额、普通及保护订单、成交历史和可获得的费用数据。提供带账户身份、币种、时间和来源的标准读模型；不支持的可选收益字段明确返回未知。前端不能为了收益读取、撤单或平仓再次增加交易所 ID 分支。

信号结果增加评估所需的参考时间、参考价格和评估周期快照。评估记录引用原组件结果，不覆盖预测；新增组件沿用通用评估与展示契约，无须安装插件或改前端代码。

### 必须通过的扩展证明

新增一个仅用于测试的平台，在后端声明“账户编码”普通字段和“访问令牌”凭据字段，其凭据不使用现有三字段名称。使用改造后不变的前端构建产物，完成选择平台、填写字段、保存、刷新确认状态、自动检查、分配资金池，并展示其测试持仓及成交。声明支持的退出操作走同一确认流程，不提供交易所专用页面。

新增一个测试信号组件，通过后端注册后出现在组件列表，可编辑权重及参数，并展示指标和表格结果。以上两个用例不能修改前端 ID 枚举、翻译映射或专用页面。

## 9. 运行控制、记录与状态接口

### 行为边界

| 操作 | 实际含义 | 必须明确的限制 |
| --- | --- | --- |
| 仅分析一次 | 获取市场数据、运行组件并融合，保存分析记录 | 可能产生模型费用；不访问交易账户或创建审批／订单 |
| 运行一次交易 | 按当前已应用配置运行完整交易流程 | 当前是全局运行，确认所有将参与的资金池；不提供无实现支持的“只运行这个池” |
| 开启／暂停自动运行 | 控制周期和条件触发的新运行 | 不自动平仓、撤单或取消正在执行的运行 |
| 停用资金池 | 阻止该池进入后续策略执行，包括手动发起的交易周期 | 不隐藏已有资产，不自动撤单或平仓 |
| 人工撤单／平仓 | 经确认退出指定账户、品种的订单或持仓 | 先停用所属池或无归属的连接；不推理、不增仓、不自动恢复策略；真实操作仍须授权 |
| 批准并执行 | 执行指定资金池已冻结的待审批计划 | 展示账户、数量、前后仓位及保护单信息；配置失效时不得执行旧计划 |
| 重新检查连接 | 使用保存后的配置进行账户只读检查 | 无交易指令，不等于交易权限验证 |

人工审批以资金池配置为准，不保留另一套未被执行链使用的全局审批开关。工作台和资金池详情展示同一个审批对象。保留审批计划的配置版本校验与失效机制。

批准后仍需在该资金池的串行执行边界内，复核最新仓位、待成交占用及总风险。若原计划已不满足约束，标为失效并要求重新生成，不能执行旧数量或静默更改用户批准的计划。

### 需要补齐的后端接口责任

- 提供独立的分析入口，提取可复用的信号分析步骤；交易入口复用该步骤后才进入执行。用结构隔离证明分析路径不可能误下单。
- 决策查询读取持久化记录，不依赖活动中的 `runtime.cycle` 对象。自动运行暂停或交易未启用时照常读取。
- 统一决策读模型支持分析记录和交易记录，包含组件结果快照、展示块、资金池过程及错误阶段。
- 就绪状态由后端按能力返回：能否分析、能否交易、不能执行的具体原因，以及缺少的配置。前端不再各自拼一套业务条件。
- 保存状态返回配置版本、已应用版本和应用失败原因；连接检查另有时间、版本和结果。
- 账户读模型、成交及收益查询独立于策略是否启用，查询持久化事实并显示同步时间；人工退出接口独立于分析和完整交易入口，操作结果可追踪。
- 回测、组件评估及告警查询各自读取持久化记录，不能依赖浏览器会话或进程内临时字典维持历史。

接口方向采用明确区分的 `POST /api/analyses` 与 `POST /api/trading-runs`，统一通过 `/api/decisions` 查询结果；人工退出使用独立的账户操作接口并保存操作记录，不伪装为一次策略决策。沿用现有任务机制处理运行，不另建通用工作流或任务平台。这些是目标接口，当前尚未实现；实施计划确定具体 DTO 与替换文件。

只读接口继续受访问安全控制，但不应被“未启动交易循环”阻断。前端网络状态不能仅根据 WebSocket 是否连接推断整个后端离线。

## 10. 风险显示必须与执行使用同一事实

当前执行路径将本次权益同时作为权益峰值传给资金池风险门，导致回撤无法反映历史损失。新页面不能把这种结果显示成有效的实时回撤保护。

资金池持久化当前权益、历史峰值、快照时间及风险评估结果。模拟与真实资金池都用实际采集的账户权益快照初始化，此后峰值随实际权益更新，不能每轮重置为当前值。同一份状态同时供风险门和页面读取。

页面区分原始目标、风险调整后的目标和计划是否可执行。回撤限制将目标压到零时，应显示“风险限制：目标持仓降至零”，允许用户理解后续可能发生的减仓；不能一律写“禁止所有交易”。

多币种总敞口使用同一时点、同一估值币种的完整资金池状态。总敞口按各持仓绝对名义金额合计，净敞口保留方向；未完成的增仓订单计入待占用，减仓单不能在成交前释放额度。评估新计划时替换本品种原仓位后再计算整池结果，保留其他品种的占用，不把全部额度逐币重复分配。保证金指标使用实际保证金数据，不将名义金额直接标为已用保证金。

本期对同一资金池的“刷新状态 → 风险判断 → 下单”串行处理，各品种依次使用更新后的占用；不同资金池可独立运行。超过总上限时压低本次增仓目标或拒绝增仓，并保留减仓能力。账户状态缺失时不扩大风险。页面显示当前占用、待成交占用、本次目标和调整原因。

本期完成目标限制、跨品种总量检查、账户能力与回撤约束。未接入该链的旧冷却、相关性、CVaR 或独立熔断状态不作为有效保护展示。复杂资金转入转出归因不在本期扩展范围，历史峰值也不能在普通保存配置时悄悄重置。

## 11. 研究与验证：可复核的回测

保留市场观察、仅分析和回测三个子入口。回测复用信号、融合和风险规则，在隔离的历史行情及本地模拟执行环境中运行，不能访问真实交易账户。执行时冻结组件参数、信任权重、模型与提示词版本、评估周期和风险参数的安全快照。

网页配置交易对、历史区间、运行周期、初始资金、手续费与滑点假设；选择当前已保存配置或已有回测中的配置快照。回测配置和记录进入数据库，不要求编辑文件或填写保存目录。数据覆盖范围、缺失的上下文来源和模型可能产生的费用在启动前可见。必须使用截至模拟时点已知的数据；缺失历史新闻等输入须明确披露，不能以当前内容替代历史事实。

每次回测保存唯一记录，不因用户没有起名称而丢失。持久化状态、参数与安全配置快照、带历史时间的权益曲线、真实模拟成交、费用以及关联决策。浏览器刷新和服务重启后，已完成记录仍能查询；重启中断的运行标为中断，第一期不做自动断点续跑。

交易次数由实际模拟成交汇总，不传空交易列表代替结果；胜率按已完成的平仓交易计算并标明统计口径，无平仓样本显示“暂无样本”。手续费、滑点和适用且可获得的资金费进入模拟资金变动；未模拟的成本显式列出。原生保护单的模拟结果必须反映历史行情触发，不能仅保存保护配置就声称已完成止损验证。

结果页展示收益、回撤、成交明细、权益曲线与决策。曲线时间对应真实历史采样点，不能统一用请求发生时的当前时间；收益与费用能回溯到模拟成交，保存后再打开不能缺失曲线。

支持选择两次回测并排比较配置差异、收益、回撤、样本数和费用。默认要求相同交易对、历史区间、运行周期、初始资金及成本假设；不同时先显示条件差异，不能直接给出哪个权重组合更优的结论。复用配置不保证模型重新调用时产生完全相同输出，因此旧结果始终保留原始组件结果，不在查看历史时重跑模型。本期不做自动搜索最优参数。

## 12. 告警与审批通知

告警进入工作台待处理事项；通知规则和送达状态放在系统设置。第一期复用现有 Webhook 通道和站内展示，不增加独立通知平台。事件由实际运行状态变化触发，至少覆盖待审批、执行失败、保护单异常、风险拒绝或压低目标、模型／平台调用失败，保留每日摘要。

用户在网页选择需要通知的事件，配置保存数据库。消息包含资金性质、账户／资金池、发生时间、简要原因及详情链接，不包含凭据或完整请求载荷。模型失败不标为已发生交易，审批消息说明等待用户操作而非订单已执行。

告警记录与外部投递结果分别持久化。关闭网页仍可投递；Webhook 失败时工作台保留事项，系统设置显示失败原因并提供重试。同一告警的刷新不重复创建事件，已审批或已解决状态跟随业务对象更新；“已读”不等于问题已经解决，也不批准交易。通知失败不撤销已经提交的交易或审批状态。

## 13. 前端结构与交互标准

复用 React、React Router、TanStack Query、现有基础控件和样式工具。页面按六个领域分组，公共层提供通用字段、凭据面板、结果块、状态提示、时间及金额格式化。

服务端数据通过查询缓存管理；表单草稿限制在当前配置领域。全局配置编辑上下文不再包裹所有业务页面。API DTO 转为页面视图数据时可以转换单位和中文格式，不自行生成风险结论或账户权限。

视觉沿用现有系统字体、深浅主题和语义色，重做布局层级。正文及字段说明不小于 14px，连续说明文字保持舒适行距；使用表格、分隔线和必要的详情区域，减少重复卡片及长表单堆叠。关键状态既有文字也有颜色。

桌面常规操作控件不小于 40px，触屏操作不小于 44px；表单支持键盘导航、可见焦点和字段关联错误。双栏在窄屏收为单栏，数据表有明确横向滚动，核心按钮不被遮挡。

页面状态必须具体：

- 尚无记录：说明数据如何产生，提供符合就绪状态的下一步，不展示伪造收益和预测。
- 保存中：仅锁定相关操作，成功后区分已保存和已应用；失败保留普通表单输入。
- 凭据未齐：列出缺项，显示“待补全凭据”，不显示无动作说明的“待检查”。
- 检查中：展示正在进行的只读检查；检查失败可以看到原因和重试入口。
- 上游模型或平台失败：显示失败环节及时间；旧数据必须标明上次更新时间。
- 暂停运行：历史与配置仍可用，说明暂停影响的新运行范围。

统一使用中文业务名称、百分比、币种与时间格式。平台品牌和模型名称保留原名；API Key 等字段附中文含义。整个日常流程无需操作参数 JSON。

根目录 [design.md](/Users/rccpony/Projects/cryptotrader-ai/design.md) 的现有规范在本规格通过后统一更新。本阶段不单独为某一新页面引入字体、主题或额外视觉系统。

## 14. 替换范围与交付顺序

以下为依赖顺序，不是已开始执行的实施计划：

1. **扩展与数据契约**：后端代码注册、参数与凭据声明、通用结果块、账户与成交读模型；同时确定对应页面的状态与验收样例。
2. **事实与运行边界**：独立分析路径、统一决策记录、账户同步与成交收益、持久化风险状态和跨币种约束；同步交付其只读页面。
3. **配置与退出流程**：动态平台表单、保存与检查、资金池及审批、人工撤单和平仓；接入待处理事项及通知。
4. **研究与效果复盘**：补齐回测成交、成本和历史曲线持久化，交付回测比较及组件方向评估；保留 Kronos 曲线和 LLM 辩论入口。
5. **整体替换与验证**：接通工作台及六入口，移除重复旧页面和无效控制，完成次日复盘与退出流程验收；经授权后做真实模型和官方模拟平台验证。

优先复用已有数据库配置的版本校验、凭据加密、审批失效判断与交易适配器，不复制一套新实现。确需调整数据结构时做一次性迁移，运行时只维护新模型。迁移前确认目标数据库并备份；不得清空现有账户、凭据和历史记录来简化重构。

旧入口及字段的实际删除清单在实施计划中逐文件列出。现有工作区未提交修改应保留，并先确认与实施文件的重叠。无用户授权不合并或推送。

| A8 | 暂停与再进入 | 暂停同时拦住周期和条件触发的新运行，历史及配置可读；页面不承诺撤销已提交订单 |
| A9 | 保存和凭据 | 已配置凭据及时间刷新后仍显示；不回显密钥；自定义凭据字段不被丢弃；更换输入与原状态清楚分开 |
| A10 | 自动连接检查 | 完整保存后自动检查一次；结果关联该版参数和凭据；参数变更后重新检查；无订单副作用 |

| A12 | 首次配置与错误 | 缺凭据、无历史、模型失败、平台失败均说明具体下一步；未开始交易也可正常浏览；不存在无限加载或伪就绪 |
| A13 | 交互与可读性 | 六个主入口、全中文操作、无参数 JSON 编辑器；关键流程通过键盘、窄屏、深浅主题检查 |
| A14 | 历史一致性 | 修改组件权重或配置后，旧决策仍展示当次版本和结果；分析记录不伪造资金池执行部分 |
| A15 | 资产与收益可核对 | 两个账户及多个品种均有独立持仓／成交记录；已实现收益、费用和权益曲线可追溯；重复同步不重复计入；缺失成本显示未知 |
| A16 | 停用与持仓可见性 | 停用池或连接后保留资产、订单与历史，策略不再对其开仓；删除或移出仍有持仓／挂单的连接被阻止，页面说明原因 |
| A17 | 人工退出 | 测试平台上先停用所属池或无归属的连接，再确认指定账户及品种撤单／平仓；不调用模型、不反向开仓、不提前撤保护；成功以同步结果确认，策略不自动恢复 |
| A18 | 跨币种总约束 | 测试权益 100、其他品种已占用 70、总敞口上限 80 时，新品种目标 40 不得照单执行；待成交增仓也占额度，同池并发不能绕过上限 |
| A19 | 组件效果复盘 | 未到期显示待评估；到期后按冻结周期和参考价计算；无方向、缺行情与失败单列；零样本不显示命中率；Kronos 原预测不被后续行情覆盖 |
| A20 | 回测可保存和比较 | 存在模拟成交的夹具显示正确成交数、平仓胜率及费用；曲线带历史时间，重启后完整可查；两次结果展示配置差异及比较条件，保护单触发影响持仓 |
| A21 | 事件告警 | 待审批和执行／保护异常产生可追踪事项；关闭网页仍可投递；Webhook 失败可见且不改变交易结果；已读不会批准交易，重复查询不重复告警 |
| A22 | 日常完整流程 | 在测试环境走通配置、仅分析、模拟执行、成交收益核对、组件复盘、停用与人工退出；全程使用网页，其他资金池未被误停或误平仓 |

自动化测试验证隔离、持久化和契约；浏览器验收验证操作流程、中文状态及重新进入页面的体验。真实模型调用和官方模拟交易验证在用户授权后单独执行并记录结果，不用真实资金验证这次界面重构。
